Scaffold a complete, reusable Terraform module.

## Stack
- **CLI:** Terraform (`terraform init`, `terraform validate`, `terraform fmt`)
- **Docs:** `terraform-docs` (generates README from variables/outputs)

## What this skill does
Creates a well-structured Terraform module following HashiCorp module development standards, with variables, outputs, examples, and a README generated by `terraform-docs`.

## Steps
1. Ask: module name/purpose, cloud provider (AWS / Azure / GCP / etc.), resources to manage
2. Create module structure:
   ```
   modules/<module-name>/
   ├── main.tf
   ├── variables.tf
   ├── outputs.tf
   ├── versions.tf
   └── examples/
       └── basic/
           ├── main.tf
           └── README.md
   ```
3. `versions.tf`: define `terraform` block with required version and `required_providers` with version constraints
4. `variables.tf`: each variable must have `description`, `type`, and sensible `default` (or no default if required). Add `validation` blocks for constrained inputs
5. `outputs.tf`: each output must have `description`. Mark sensitive outputs with `sensitive = true`
6. `main.tf`: implement the resources; use variables — no hardcoded values
7. `examples/basic/main.tf`: minimal working example calling the module
8. Generate README: `terraform-docs markdown . > README.md` (or write manually if tool unavailable)
9. Validate: `terraform init && terraform validate`

## Constraints
- Pin provider versions in `versions.tf` — never use `>= x` without an upper bound for patch releases
- No secrets in examples — use `var.` references
