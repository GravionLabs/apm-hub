---
name: review-fanout
description: 'Parallel multi-dimension review of a diff; returns APPROVE or CHANGES_REQUESTED. Use for "review my changes" or "review PR #N".'
---

Read-only: never edit or commit.

## Steps

1. **Input** — write ONE package file instead of pasting the diff: `<state>/<issue>/review-<n>.diff` (else a unique file in `$TMPDIR`) with `git log --oneline <base>..<head>`, `git diff --stat <base>..<head>` and `git diff -U3 <base>..<head>` (code hunks only, documentation paths excluded, see Documentation below); no range given → `git diff HEAD`. PR: `gh pr view <nr> --json commits,files` + `gh pr diff <nr>` (`<nr>` must be an integer). Redirect into the file so nothing enters your context. Empty diff → stop. Copy `<state>/<pbi>/verify.json` (`status`, `summary`, `tests`) as one `verify: <status> — <summary> — tests <n>/<m>` line into the head of the package file; the file missing → `verify: unknown`; never run the suite. Before any dispatch (step 2 and step 4) check the package file exists and is non-empty; otherwise stop, report `incomplete: true` and dispatch nothing. Filter out generated files, lockfiles, goldens/snapshots, minified/bundled assets, `dist/`, `coverage/`, `docs/*-list.md` and binary files with `-- . ':!<pattern>'` pathspecs; the list is in `references/package-filter.md`. **Documentation**: hunks of `docs/**/*.md`, `CHANGELOG.md`, `README*.md` and `site/**` (minus the filter list) go into a trailing section opened by the marker line `=== DOCUMENTATION ===` (alone on its line, column 0) written LAST, after the issue and invariants sections (`git diff -U3 <range> -- <doc patterns>` as `:(glob)` pathspecs, patterns in `references/package-filter.md`; a PR: `gh pr diff <nr>` sections of those files, same marker, -U3 not available there so keep the hunks as printed); none → no marker. Measure with `pwsh scripts/Get-PackageSize.ps1 -Path <package>`. **Re-review** after a fix round (the caller passes the previous round's `review.json`): the package holds only the fix diff `<last review HEAD>..HEAD` plus the earlier findings (`file:line severity title — fixed|open|pr-body|declined: <reason>|deferred: <need>`), never the full diff again (`-U3`, same Documentation split). Optional input **rulings file** (`<state>/<pbi>/rulings.json`, array `{file,line,severity,title,status,reason?}`): the statuses come from it, an earlier finding without an entry is `open`. Optional issue number (argument, branch `<type>/<nr>-<slug>`, or `Closes #n` in the range): append issue title, body and Task sub-issue bodies to the package file, see `references/spec-dimension.md`; none found → `spec` reports "no spec available" as advisory. With an issue found (also in a re-review) and `<state>/<issue>/plan.json` present, append the plan invariants as `references/correctness-dimension.md` describes. **Size**: after writing the package (the script computes it) set `bytes` (file length), `tokensEstimated` = ceil(bytes / 4) (an estimate), `hunks` (`^@@` lines before the marker) and `docsHunks` (after it). Above 15000 estimated tokens (a caller may pass another threshold) add `oversize: {threshold, largest: [{file, bytes}, top 3]}` and the summary line `package ~<n>k tokens > 15k — largest: <files>`; never split the package.
2. **Fan out**
   - **Classify** first, only for a local range or the working tree (PR number without a resolvable local `<base>..<head>`: `full`, do not run it).
   - Run it only when every ref matches `^[A-Za-z0-9._/@~^-]+$` and none starts with `-`; any other ref is `full` without running it (refs may contain shell metacharacters).
   - Range: `pwsh -NoProfile -File scripts/Classify-Diff.ps1 -Range "<base>..<head>"`; working tree (no range): the same without `-Range`. The caller's `--full` or "review full" maps to `-Force full`.
   - It prints `{mode,dimensions,reason}`: run only those `dimensions` (a dimension list given by the caller replaces them); script error, no output or invalid JSON is `full`. Location classes, rules and security triggers (the script is authoritative): `references/mechanical-classifier.md`. `docs` and `text` run the listed dimensions.
   - **Dispatch**: load `detect-techstack`. Spawn one fresh `reviewer` agent per dimension of the chosen mode in a single parallel batch (a generic read-only sub-agent when `reviewer` is not installed), each given only the package path, the dimension and its brief (`reviewer` is dispatched only from `review-fanout`, wherever it runs: inline or inside the `review-lead` agent):
     - `correctness`: bugs, edge cases, error handling, races; check each invariant in the issue section: a violated one is HIGH, `evidence` quotes the invariant and the diff line (goes through verify like any HIGH, refuted → advisory); no `## Invariants` section: unchanged, see `references/correctness-dimension.md`
     - Brief for `correctness`, `security`, `tests`: stop reading at the `=== DOCUMENTATION ===` line; `spec` and `conventions` read it.
     - `security`: injection, authz, secrets, unsafe input (always when auth/crypto/network/SQL files changed)
     - `conventions`: the `code-review` skill (it loads each language's `## Review rules`; stack skill not installed → one advisory finding "install `<stack>@apm-hub`")
     - `tests`: judge coverage and test quality from the diff and the package `verify:` line, never execute tests; missing or weak tests; tests coupled to internals, tautological assertions (expected value recomputed like the code), missing behavior tests (rules: `implementation` skill, `references/test-quality.md`)
     - `spec`: issue criteria missing, partial or wrong, and scope creep; brief and severities in `references/spec-dimension.md`

   Each returns `[{file,line,severity: CRITICAL|HIGH|MEDIUM|LOW,evidence,issue}]`. A finding with empty or missing `file` or a `line` below 1 is invalid, never advisory: drop it and mark its dimension failed. Advisories without a natural location (`spec` "no spec available", `conventions` "install `<stack>@apm-hub`") use the placeholder `file` = the package path, `line` = 1. A reply `[]` plus a `NO_PACKAGE:` line also marks the dimension failed.
   **No active waiting**: dispatch all reviewers in ONE message, then wait for their replies. Never run `sleep` or `Start-Sleep`, never poll files, ledgers or `review.json` for reviewer completion. The calls return the results: Claude Code `Agent` returns the reply, OpenCode `task()` awaits it, Copilot `runSubagent` returns it.
   Claude: `Agent` calls with `subagent_type: reviewer` in one message · OpenCode: parallel `task()` with agent `reviewer` · VS Code Copilot: `#runSubagent` with agent `reviewer` · otherwise run inline sequentially.
3. **Rulings pass**, before dedupe and verify, only with a readable rulings file (missing, unreadable or invalid → skip the pass, nothing dropped, behaviour unchanged): drop a new MEDIUM/LOW finding whose `file` equals an entry's `file` and whose normalised `issue` equals that entry's normalised `title`, for entries with status `pr-body`, `declined` or `deferred`; normalise = lowercase, collapse whitespace, strip trailing punctuation; `line` is ignored. A CRITICAL/HIGH match is never dropped: it stays and goes through verify. Dropped findings are collected in `suppressed`.
   **Dedupe** by file + normalized evidence; keep highest severity. Never merge `spec` with `conventions` findings. It runs after all dimensions reported and applies the verify results already known: a finding refuted in early verify stays refuted (advisory) when deduped.
4. **Verify** — a sub-agent (given the package path, not the diff) tries to disprove each CRITICAL/HIGH finding: `confirmed`, `refuted` (→ advisory), `unverifiable` (stays blocking).
   **Early verify**: start it for a dimension as soon as its result contains a CRITICAL or HIGH finding, while other dimensions still run; one verify batch (a single message) per arriving dimension, no waiting for the rest. The verdict waits for all dimensions and all verify results. Fail-closed rules apply unchanged: a verify that fails or returns nothing leaves the finding `unverifiable` (blocking).

## Output (JSON returned to the caller; a machine-readable copy for the caller goes to `<state>/<issue>/review.json`, else next to the package file in `$TMPDIR`)

`{"mode":"mechanical|docs|text|full","dimensions":[],"verdict":"APPROVE|CHANGES_REQUESTED","incomplete":false,"failedDimensions":[],"blocking":[{file,line,severity,issue,evidence}],"advisory":[],"suppressed":[],"package":{"bytes":0,"tokensEstimated":0,"hunks":0,"docsHunks":0}}` (`suppressed` = the findings dropped by the rulings pass, `[]` without a rulings file; plus `package.oversize` when above the threshold; also in `review.json`)

Fail closed: a failed dimension (including invalid findings or `NO_PACKAGE`) → `incomplete: true` and `CHANGES_REQUESTED`. Any blocking finding → `CHANGES_REQUESTED`.
