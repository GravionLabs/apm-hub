## Purpose

Apply modern C# idioms to every `.cs` file changed in the current branch. The goal is to leave touched files cleaner than found — no sprawling refactors of untouched code.

---

## Step 1 — Identify Touched Files

```powershell
git diff origin/main --name-only | Where-Object { $_ -match '\.cs$' }
```

Exclude auto-generated files:
- `*.designer.cs`, `*.g.cs`, `*.g.i.cs`
- Files in `Migrations/`
- Files containing `<auto-generated>` or `[GeneratedCode]` in the first 10 lines

---

## Step 2 — Detect Target Framework

```powershell
Get-ChildItem -Recurse -Include "*.csproj" | 
  Select-String '<TargetFramework[s]?>(.*?)</TargetFramework' |
  Select-Object -First 1
```

Use the target framework to determine which language features are available:

| Feature | Min version |
|---|---|
| File-scoped namespaces | C# 10 / .NET 6 |
| Global usings | C# 10 / .NET 6 |
| `required` modifier | C# 11 / .NET 7 |
| Primary constructors (classes) | C# 12 / .NET 8 |
| Collection expressions `[]` | C# 12 / .NET 8 |
| `field` keyword (semi-auto properties) | C# 13 / .NET 9 |

Only apply features available for the detected framework. When in doubt, check the `<LangVersion>` in `.csproj` or `Directory.Build.props`.

---

## Step 3 — Apply Modernizations

Process each file. Apply ALL applicable rules below in a single pass per file.

---

### 🔵 File-Scoped Namespaces (C# 10+)

**Before:**
```csharp
namespace MyApp.Services
{
    public class UserService
    {
        ...
    }
}
```

**After:**
```csharp
namespace MyApp.Services;

public class UserService
{
    ...
}
```

Rules:
- Only convert when the file has exactly **one namespace block**.
- Remove the now-unnecessary outer braces and reduce indentation by one level for all contained types.
- Do not convert files with multiple namespace declarations.

---

### 🔵 Remove #region / #endregion

Remove all `#region` and `#endregion` directives — do NOT remove the code inside them, only the directives themselves.

**Before:**
```csharp
#region Private Fields
private readonly ILogger<UserService> _logger;
private readonly IUserRepository _repository;
#endregion

#region Constructor
public UserService(ILogger<UserService> logger, IUserRepository repository)
{
    _logger = logger;
    _repository = repository;
}
#endregion
```

**After:**
```csharp
private readonly ILogger<UserService> _logger;
private readonly IUserRepository _repository;

public UserService(ILogger<UserService> logger, IUserRepository repository)
{
    _logger = logger;
    _repository = repository;
}
```

---

### 🔵 Primary Constructors (C# 12+)

Convert simple constructor-with-field-assignment patterns to primary constructors when:
- All constructor parameters are assigned directly to `readonly` fields
- No other logic in the constructor body
- Fields are only set in the constructor (not mutated elsewhere)

**Before:**
```csharp
public class OrderService
{
    private readonly IOrderRepository _repository;
    private readonly ILogger<OrderService> _logger;

    public OrderService(IOrderRepository repository, ILogger<OrderService> logger)
    {
        _repository = repository;
        _logger = logger;
    }
}
```

**After:**
```csharp
public class OrderService(IOrderRepository repository, ILogger<OrderService> logger)
{
    private readonly IOrderRepository _repository = repository;
    private readonly ILogger<OrderService> _logger = logger;
}
```

> **Note:** If the class has logic in the constructor beyond pure assignment, keep the explicit constructor. Primary constructors shine for pure DI classes.

---

### 🔵 `field` Keyword for Semi-Auto Properties (C# 13+)

Replace explicit backing fields + property pair when the property only gets/sets the field with no extra logic:

**Before:**
```csharp
private string _name;
public string Name
{
    get => _name;
    set => _name = value;
}
```

**After:**
```csharp
public string Name
{
    get;
    set;
}
```
(or if validation exists in the setter, use the `field` keyword):
```csharp
public string Name
{
    get;
    set => field = value?.Trim() ?? throw new ArgumentNullException(nameof(value));
}
```

Only apply when the backing field is **exclusively** used by the property. If the field is referenced elsewhere in the class, leave it as-is.

---

### 🔵 Collection Expressions (C# 12+)

**Before:**
```csharp
var items = new List<string>();
var ids = new List<int> { 1, 2, 3 };
string[] names = new string[] { "a", "b" };
IEnumerable<int> empty = Enumerable.Empty<int>();
```

**After:**
```csharp
List<string> items = [];
List<int> ids = [1, 2, 3];
string[] names = ["a", "b"];
IEnumerable<int> empty = [];
```

---

### 🔵 Using Declarations (C# 8+)

**Before:**
```csharp
using (var stream = new FileStream(path, FileMode.Open))
{
    // ...
}
```

**After:**
```csharp
using var stream = new FileStream(path, FileMode.Open);
// ...
```

Only apply when the `using` block is at the end of a method or the scope is clear. Do not apply when the disposal boundary matters mid-method.

---

### 🔵 Target-Typed `new` (C# 9+)

**Before:**
```csharp
Dictionary<string, List<int>> map = new Dictionary<string, List<int>>();
HttpClient client = new HttpClient();
```

**After:**
```csharp
Dictionary<string, List<int>> map = new();
HttpClient client = new();
```

Only apply when the type is explicit on the left-hand side. Do not apply to `var`.

---

### 🔵 Pattern Matching Modernization (C# 8+)

**Before:**
```csharp
if (obj is MyType)
{
    var typed = (MyType)obj;
}

if (x != null && x.IsActive)
```

**After:**
```csharp
if (obj is MyType typed)
{
}

if (x is { IsActive: true })
```

**Null checks:**
```csharp
// Before
if (value == null) throw new ArgumentNullException(nameof(value));
if (value != null) DoSomething(value);

// After
if (value is null) throw new ArgumentNullException(nameof(value));
if (value is not null) DoSomething(value);
```

---

### 🔵 Switch Expressions (C# 8+)

**Before:**
```csharp
string result;
switch (status)
{
    case Status.Active: result = "active"; break;
    case Status.Inactive: result = "inactive"; break;
    default: result = "unknown"; break;
}
```

**After:**
```csharp
string result = status switch
{
    Status.Active => "active",
    Status.Inactive => "inactive",
    _ => "unknown"
};
```

Only apply when the switch assigns a single variable or returns a value. Do not apply when cases have complex multi-statement bodies.

---

### 🔵 String Interpolation over `string.Format` (C# 6+)

**Before:**
```csharp
var msg = string.Format("User {0} has {1} items", name, count);
var msg2 = "Hello " + name + ", you have " + count + " items";
```

**After:**
```csharp
var msg = $"User {name} has {count} items";
var msg2 = $"Hello {name}, you have {count} items";
```

---

### 🔵 `nameof()` for Member References (C# 6+)

**Before:**
```csharp
throw new ArgumentNullException("userId");
_logger.LogError("Error in UserService");
Guard.Against.Null(value, "value");
```

**After:**
```csharp
throw new ArgumentNullException(nameof(userId));
_logger.LogError("Error in {Service}", nameof(UserService));
Guard.Against.Null(value, nameof(value));
```

---

### 🔵 `var` Where Type Is Obvious

**Before:**
```csharp
IEnumerable<User> users = await _repository.GetAllAsync();
List<string> names = new List<string>();
```

**After:**
```csharp
var users = await _repository.GetAllAsync();
var names = new List<string>();
```

Do NOT use `var` when the type is not obvious from the right-hand side (e.g., factory methods, ambiguous return types).

---

### 🔵 Throw Expressions (C# 7+)

**Before:**
```csharp
public UserService(IRepository repository)
{
    if (repository == null) throw new ArgumentNullException(nameof(repository));
    _repository = repository;
}
```

**After:**
```csharp
public UserService(IRepository repository)
{
    _repository = repository ?? throw new ArgumentNullException(nameof(repository));
}
```

---

### 🔵 Remove Redundant `else` After Return/Throw

**Before:**
```csharp
if (user is null)
{
    return NotFound();
}
else
{
    return Ok(user);
}
```

**After:**
```csharp
if (user is null)
    return NotFound();

return Ok(user);
```

## Step 4 — Build Verification

After modernizing all files:

```powershell
dotnet build --no-incremental 2>&1 | Select-String "error" | head -30
```

If the build fails:
1. Identify which modernization caused the error.
2. Revert that specific change in that specific file.
3. Re-run build until green.

Do not proceed with a broken build.

## Rules

- **Only touch files already modified in the current branch** — never modernize unrelated files.
- **Never break functionality** — if a modernization is ambiguous or risky (e.g. primary constructor when constructor has side effects), skip it for that instance.
- **Preserve XML doc comments** — `/// <summary>` blocks must be left intact.
- **Do not remove or reorder using directives** — that is the formatter's job.
- **Build must be green after this agent** — revert any change that breaks the build.
